Why env-vault

A smaller,
focused secret workflow.

Instead of leaving credentials in plaintext files, keep the stored vault encrypted and expose secrets to the application only when it needs them.

Encrypted vault

Convert your .env values into an encrypted .env.vault file protected by a password.

Runtime injection

Launch your application through env-vault and make the recovered values available through the normal process.env API.

Password rotation

Change the password protecting an existing vault without manually rebuilding the entire workflow.

Algorithm

From plaintext to protected runtime secrets.

The workflow separates encrypted storage from application execution. The environment file is transformed into a protected vault, then recovered when the application needs its environment.

Real-world use cases

What do you actually
use env-vault for?

Environment variables commonly contain API keys, database credentials, signing secrets, service tokens and configuration that should not live in plaintext. env-vault provides a lightweight way to protect those values in Node.js projects.

01

Local development

Your local .env may contain database passwords, JWT secrets, API keys and third-party credentials. Encrypt those values into .env.vault instead of keeping the sensitive data in an easily readable file.

02

Sharing configuration with a team

Teams sometimes need the same environment configuration. An encrypted vault can be stored alongside the project while the vault password is distributed through a separate secure channel.

03

Git repositories

Instead of committing plaintext credentials to Git, keep the environment values protected. The plaintext .env should remain excluded from the repository, while your encrypted vault can be handled according to your team's security policy.

04

CI/CD deployments

Automated environments cannot answer an interactive password prompt. env-vault supports ENV_VAULT_PASSWORD, allowing a CI/CD system to provide the vault password from its own protected secret configuration.

05

Staging and production

A Node.js service can be started through env-vault so that the application receives its configuration through process.env. This means existing code can continue using the standard Node.js environment API.

06

Credential rotation

When a vault password needs to change, use the rotation workflow instead of manually recreating the entire encrypted environment setup.

07

API credentials

Protect values such as private API tokens, payment service credentials, email service keys, OAuth secrets, webhook signing keys and other application configuration.

08

Database credentials

Database URLs and passwords frequently live in environment variables. Keeping those values encrypted at rest reduces the chance of accidentally exposing them through ordinary plaintext configuration files.

CLI reference

This is the complete command reference. Start with installation and initialization, encrypt your environment, then use the runtime command whenever your application needs the protected values.

Recommended workflowInstall the package, initialize the vault, encrypt your environment, and launch your application through the runtime command.
01

Install

Add env-vault to your Node.js project.

$npm install uixphuke-env-vault
02

Initialize

Create the initial vault workflow.

$npx env-vault init
03

Encrypt

Turn .env into .env.vault.

$npx env-vault encrypt
04

Decrypt

Recover the environment into .env.

$npx env-vault decrypt
05

Run

Start your app with recovered process.env values.

$npx env-vault run -- node server.js
06

Environment Variable

Useful for CI/CD and non-interactive environments.

$ENV_VAULT_PASSWORD="your-password" npx env-vault run -- node server.js
07

Rotate

Change the password protecting the vault.

$npx env-vault rotate
08

Status

Inspect vault metadata without exposing secrets.

$npx env-vault status
09

Version

Show the installed env-vault CLI version.

$npx env-vault version
09

Help

Display available commands and usage information.

$npx env-vault --help

Security model

Protect the stored data.
Minimize plaintext exposure.

env-vault is intentionally focused: encrypted environment storage, password-protected access, runtime injection, authentication and password rotation.

Encrypted at rest

The vault stores protected environment data rather than the original plaintext values.

Authentication

Incorrect passwords and invalid or modified vault data fail authentication instead of silently returning incorrect secrets.

Password rotation

Replace the password protecting an existing vault when credentials need to be rotated.

CI/CD support

Automated environments can provide ENV_VAULT_PASSWORD instead of relying on interactive password entry.

Important security boundary

env-vault is a lightweight encrypted environment workflow, not a centralized cloud secret-management platform. Protect the vault password carefully, never commit plaintext credentials, and use your CI/CD or infrastructure provider's secure secret storage for the password itself.

CI / CD

Built for automated
environments too.

Interactive password prompts are useful locally but unsuitable for automated deployments. env-vault can read the vault password from the environment when running in CI/CD.

Keep the vault password outside the repository.

Configure your CI/CD provider to expose the vault password as a protected environment secret. The application can then start through the env-vault runtime workflow without storing the password in source control.

Keep plaintext local.

The original .env file contains your actual environment values. env-vault transforms those values into an encrypted vault for protected storage.

When the application starts through the runtime flow, the recovered values become available through the normal Node.js environment interface.

Do not commit plaintext credentials, API keys, database passwords or other sensitive values to public repositories.
